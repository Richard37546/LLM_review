# 13 DPO｜直接偏好优化

## 你现在应该记住什么
1) DPO（Direct Preference Optimization）和 RLHF 的目标相近，都是让模型更符合人类偏好。  
2) DPO 的关键特点是：不再显式训练 reward model，也不再显式跑 PPO，而是直接用偏好对数据优化策略模型。  
3) DPO 不是否定“奖励思想”，而是把奖励-策略关系隐式吸收到一个更直接的优化目标里。  
4) DPO 训练形式更像一种偏好监督优化，因此通常比 PPO 更简单、更稳定。  
5) DPO 不是万能替代所有 RL，它特别适合 LLM 的偏好对齐场景。

---

## 专有名词解释
- **Preference Pair（偏好对）**：同一个 prompt 下的 winner / loser 回答对。  
- **Winner / Loser**：人类更喜欢的回答 / 相对较差的回答。  
- **DPO（Direct Preference Optimization）**：直接利用偏好数据优化策略模型的方法。  
- **Reference Model**：冻结的参考模型，用于形成相对约束，防止策略偏离太远。  
- **RLHF**：先学 reward model，再用 PPO 等 RL 方法优化策略的偏好对齐路线。  
- **Reward Model**：学习人类偏好的打分模型。  
- **PPO**：RLHF 中常用的稳定策略优化算法。

---

## 为什么 RLHF 之后还会出现 DPO
传统 RLHF 的典型流程是：

1) SFT  
2) 训练 Reward Model  
3) 用 PPO 优化策略

这条链路有效，但也有明显痛点：

### 1. 工程复杂
要维护：
- policy model  
- reward model  
- reference model  
- 甚至还可能有 value model / critic  
- PPO rollout 训练链条

### 2. 训练不稳定
PPO 比普通监督学习更难训，对超参数也更敏感。

### 3. 容易 reward hacking
模型可能学会骗过奖励模型，而不是真正变得更符合人类偏好。

所以就会自然产生一个问题：

> 既然我们原始数据本来就是“winner 比 loser 更好”，能不能直接用这些偏好对数据训练策略，而不再绕一圈先训练 RM 再跑 PPO？

这就是 DPO 的出发点。

---

## DPO 的核心目标
DPO 最直观的目标是：

> 对于同一个 prompt，让模型更偏向生成 winner，而不是 loser。

如果有一条偏好数据：

\[
(x, y_w, y_l)
\]

其中：
- \(x\)：prompt  
- \(y_w\)：winner  
- \(y_l\)：loser

那么 DPO 就希望模型对 \(y_w\) 的相对偏好更高。

---

## DPO 和 RLHF 的关系
### 相同点
- 都在做偏好对齐  
- 都想让模型更符合人类偏好  
- 都依赖 preference data

### 不同点
- **RLHF**：偏好数据 → Reward Model → PPO  
- **DPO**：偏好数据 → 直接优化策略

所以一句最稳的总结是：

> DPO 可以看成对 RLHF 偏好优化目标的一种更直接、更简化的实现路径。

---

## DPO 最本质的思想
DPO 的理论出发点并不是“完全抛弃奖励”，而是观察到：

> 在带 KL 正则的 RLHF 目标下，最优策略和奖励函数之间存在对应关系。

这意味着：

- 我们不一定要显式先训练出一个独立 reward model；  
- 可以把这种“奖励-策略关系”隐式吸收到一个直接优化策略的目标里。

所以更准确的说法是：

> DPO 不是否定奖励思想，而是把奖励模型那一层“折叠”进了一个更直接的偏好优化目标。

---

## DPO 的训练数据长什么样
和 reward model 的偏好训练数据本质上一样，通常是：

\[
(prompt, winner, loser)
\]

也就是对同一个 prompt，人类告诉我们：
> winner 比 loser 更好。

区别不在数据本身，而在于“怎么用这些数据”。

---

## DPO 到底在比较什么
对于同一个 prompt：

- 当前策略模型会给 winner 一个概率  
- 也会给 loser 一个概率

DPO 的目标就是：

> 让当前策略相对于参考模型，更偏向 winner，而不是 loser。

所以 DPO 不只是简单提高 winner 概率，而是优化：

- winner 相对于 loser 的偏好关系  
- 且这种偏好关系是相对于 reference model 来定义的

---

## 为什么 DPO 通常还需要 reference model
很多人会误以为：

- DPO 不需要 reward model  
- 所以是不是 reference model 也不要了？

不是。

Reference model 的作用依然很重要，它本质上还是在提供一个“不要偏得太离谱”的基准。  
通常它会是一个冻结的 SFT 模型副本。

直觉上：

> 我们希望新策略更偏向 winner，但这个“更偏向”是相对于一个参考分布来定义的，而不是毫无约束地猛推概率。

所以 reference model 在 DPO 里依然起到“稳住分布”的作用。

---

## DPO 和 SFT 的区别
### SFT
给定 prompt 和一个理想回答，最大化这个回答的似然。  
它本质上是在做“单答案模仿”。

### DPO
给定 prompt、winner、loser，优化模型：
- 更偏向 winner  
- 少偏向 loser

它不是单答案模仿，而是偏好比较优化。

一句话总结：

> SFT 优化的是“像参考答案”，DPO 优化的是“更偏向人类更喜欢的答案而不是较差答案”。

---

## DPO 和 RLHF / PPO 的区别
### 1. 是否显式训练 reward model
- RLHF：通常需要  
- DPO：不需要显式独立 RM

### 2. 是否需要显式强化学习优化
- RLHF：通常用 PPO  
- DPO：不需要显式 PPO rollout

### 3. 训练形式
- RLHF：更像强化学习流程  
- DPO：更像偏好监督优化 / 分类式优化

### 4. 工程复杂度
- RLHF：复杂、敏感  
- DPO：更简单、更稳、更容易复现

---

## 为什么很多人觉得 DPO 更简单、更稳
因为 DPO 跳过了 RLHF 中最重、最不稳定的部分：

- 不单独训练 RM  
- 不显式跑 PPO  
- 不需要处理那么多 RL 细节和超参数

所以从工程角度看，DPO 常常更适合：

- 快速实验  
- 较低复杂度实现  
- 更稳定的偏好微调流程

---

## DPO 的优点
1) **流程更简单**：链路短  
2) **训练更稳定**：少了 RL 训练中的很多不稳定因素  
3) **更容易实现与复现**  
4) **直接利用偏好对数据**，没有再多绕一层 proxy

---

## DPO 的局限
1) 仍然依赖偏好数据质量  
2) 更偏向离线偏好优化，而不是通用强化学习  
3) 不代表在所有 RL 场景都替代 PPO / RLHF  
4) 它非常适合 LLM 对齐，但不是“任何序列决策问题都优先用 DPO”

---

## DPO 在整条链里的位置
你可以这样看：

- **预训练**：学能力  
- **SFT**：学助手行为  
- **RLHF / DPO**：学偏好对齐

其中：
- RLHF 是“RM + PPO”的经典路线  
- DPO 是偏好对齐阶段的一种更直接的简化路线

---

## DPO 到底算不算强化学习
这是一个很容易被问的问题。

更稳妥的回答是：

> 从训练形式看，DPO 更像一种直接的偏好监督优化，而不是传统意义上的强化学习流程；但从理论来源看，它和带 KL 正则的 RLHF 目标是相连的。

这比简单说“是”或者“不是”都更成熟。

---

## 常见误区
1) 以为 DPO 完全不需要 reward 概念：不对，它只是不用显式训练独立 reward model。  
2) 以为 DPO 不需要 reference model：通常仍然需要。  
3) 以为 DPO 就是 SFT：不对，SFT 是单答案模仿，DPO 是偏好对优化。  
4) 以为 DPO 一定全面优于 RLHF：不严谨，它更适合 LLM 偏好对齐，但不是所有 RL 场景的通用替代。  
5) 以为 DPO 是纯经验 trick：它有明确的理论来源。
